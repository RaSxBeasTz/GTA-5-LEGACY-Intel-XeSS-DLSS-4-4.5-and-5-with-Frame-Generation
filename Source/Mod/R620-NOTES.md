# R620 single visible presentation experiment

The saved CPU trace now maps the dominant FG-worker wait to a concrete wakeup: worker56912 waits inside igxess_fg.dll+0x1CAC86, and presenter56784 releases it via SetEvent at igxess_fg.dll+0x1CA4EC.311 measured blocked intervals have that wakeup path, with only a few milliseconds total ready-to-run delay. This establishes a presenter dependency, not CPU starvation or camera arithmetic. SDK resource-tagging and submission order were checked against the pinned Intel developer guide; no FPS cap or obvious tagging-order violation was found. The overlay-disabled user run did not recover FPS, so overlays are not treated as the established fix.

R619 merely added nonblocking flags to the original image Present and fell back after4attempts. R620 tests an actually different presentation path: while fresh FG output is visible, invoke this mod's real capture callback explicitly once, then call the native Present chain with DXGI_PRESENT_TEST only. Thus native visibility/error checking remains but the original image is not submitted for display. Test-callback dispatch is suppressed for our own capture to prevent duplicates. If ScriptHook omits callbacks on TEST, explicit capture still runs.

An independent native D3D11 fence is signaled/flushed after each experimental frame. The next native Present entry waits for that prior fence, bounding queued work to the current/prior frame. Wait timeout remains20ms with2ms checks. Native queue setting remains1, although the explicit fence changes effective GPU admission in the experimental mode. No shared-colour handback or FG preparation/generation fences are removed. Source FPS remains uncapped.

Fallbacks:1=GPU gate failed/timed out;2=explicit capture callback did not acknowledge;3=unsupported TEST flags;4=focus/output/mode changed;5=genuine native device/presentation error;6=fence signal failed. Reason code and suppressed-image count are logged. Normal presentation is restored if FG is stale/hidden, focus changes, F9 turns off, F8 finishes/cancels, or a safety check fails. Only expected native DXGI_STATUS_OCCLUDED behind verified fresh FG is normalized; genuine device errors propagate. Nonzero source sync/flags are passed through unchanged. Source swapchain retargeting is refused.

Normal remains default. F8 phases: x4_native_normal / x4_native_test_only / x4_native_normal_repeat,3seconds settle+12seconds sample each, full-resolution inputs and x4. A fallback aborts the comparison rather than reporting an invalid improvement. No WPR/PIX profiler is launched for this test.

Validation:64 actual Arc A770 D3D11 render/fence cycles with zero native image-presentation count increase and correct BGRA GPU readback; exact-once callback including a chain that skips TEST callbacks; occlusion normalization; unsupported flag retry; genuine device error propagation; focus/F9/comparison transition during callback; bounded timeout and normal restoration. Comparison orchestration regression passes completion, F8/F9/focus/timeout, unsupported mode and automatic fallback. Recorder parser/continuous tests pass. Release build/protected integrity passes with existing C4244 warnings.

Limitations: standalone hardware tests do not establish GTA/ScriptHook compatibility, improved FPS, correct game frame statistics, long-session resource behavior or visual quality. Other addons relying only on ScriptHook's native image-presentation callback may behave differently during TEST-only mode if ScriptHook suppresses their callbacks. The experiment is temporary; do not promote it without complete comparison and visual confirmation. Protected camera, temporal shaders, ghosting DLL and installed freezing DLL remain unchanged. R619 experimental header/smoke source retained in tests/baseline.
